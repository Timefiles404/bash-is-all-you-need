# 新增阶段

每个 `stages/NN-name/` 都是 Agent 在课程某一点上的**完整、独立的快照**。
读者应该能直接 `diff stages/NN stages/NN+1`，一眼看出这一步只多了一个
想法。

## 没得商量的规则

- **复制上一个阶段，不要 import 它。** 快照之间的重复是故意留的。绝不要
  把共享代码抽成公共包。
- **不许有依赖**：除了标准库和 `golang.org/x/sys`，别的都不行。阶段 08
  是唯一的例外，而那一章大半篇幅就是在论证它凭什么配得上这个位置。
- **每个阶段只装一个想法。** diff 里冒出两个，那就是两个阶段。

## 这一章

`docs/NN-name.md`，下面这些一条都不能少：

- 前三段把想法讲完，包括它的代价。
- **"一次真实运行"** 一节，里面的输出必须是你真抓下来的。编出来的例子
  会把这个仓库的立论整个抽掉。
- 至少一次**实测**，说清对照的是哪两路，点明混淆因素。实测结果要是打了
  这一章自己的脸，照实写——阶段 04 测出短会话里不打缓存标记反而比打了
  强，阶段 05 测出上下文压缩花掉的比省下的多。两章都照实写了。
- 至少一处**写这一章时发现的失败**。这是整个仓库最值钱的段落。要去找
  它们，别去写一篇干净的叙事。
- 练习要故意弄坏点什么。

## 提交前的验证

```sh
gofmt -l stages/                        # 必须是空的
go vet ./...                            # 必须干净
go test -race ./...                     # 必须全绿
GOOS=linux go build ./stages/...        # 平台相关的文件是真的要编译过
GOOS=darwin go build ./stages/...
grep -rnE 'sk-[A-Za-z0-9]{20,}' --exclude-dir=.git .   # 绝不能有 key
```

Agent 只在 `sandbox/` 里跑——它会照模型说的去执行。

## 注释

密度照着 `stages/04-the-cache/render.go` 来。注释解释的是*为什么*，并且
点名它防住的是哪个故障；注释绝不复述代码。
