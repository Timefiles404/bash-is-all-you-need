# 阶段 00：主循环

**你会做出什么**：一个能翻代码、跑命令、改文件、再回头验证自己成果的
coding Agent。

**代价**：一个文件，200 行左右的 Go，标准库以外一个依赖都没有。

这个比例就是第一课。Agent 本身不是什么大工程。这个仓库里所有的硬骨头
都在这一阶段**之后**，而且没有一块是为了让 Agent 更聪明。

---

## 按这个顺序读

`stages/00-loop/main.go`，三个函数：

1. **`main()`** —— 主循环。先读它，其余全是它调用的细节。
2. **`callModel()`** —— 一次 HTTP POST。这里没有 SDK，而 SDK 底下也就是
   这么点东西。
3. **`runBash()`** —— 十行。Agent 能做的一切都得从这里过。

## 循环长什么样

```
用户输入一个任务
  └─ 把 {role:"user"} append 到 messages
     └─ 循环：
        ├─ 带上整个 message 数组 POST /chat/completions
        ├─ 把 assistant 的回复 append 到 messages
        ├─ 没有 tool_calls？  → 打印文本，退出循环
        └─ 对每个 tool_call：
             跑掉那条命令
             把 {role:"tool", tool_call_id, content: output} append 上去
           → 回到开头
```

两条不变式撑着整个循环，而且都是承重墙：

**消息数组只增不删。** 不改、不删、不重排。这段对话**就是** Agent 的记忆，
每个请求都把它整个再发一遍。阶段 05 是我们第一次动这条规矩，破它是要
交学费的。

**每个工具调用都得有结果回去。** 模型要了三条命令你只回两条，下一个
请求直接不合法。命令跑挂了也一样——失败**本身**就是那个结果，下面细说。

---

## 错误是观察，不是异常

`runBash` 里最常见的新手错误就这一个：

```go
out, err := cmd.CombinedOutput()
if err != nil {
    return err          // ← 错了
}
```

退出码非零，不代表你的程序坏了。它产出了信息，而该对这份信息作出反应的
是模型，不是你。看下面那次真实运行：`python stats.py` 以 1 退出，吐出
一段 `ZeroDivisionError` 的 traceback，我们把 traceback 原样递回去，模型
靠它定位到了 bug。要是那一行返回了 Go 的 error，Agent 就正好停在它刚开始
有用的那一刻。

这个直觉一路往上都成立：你的活是把世界如实报给模型，不是替模型把世界
挡住。

## 实验：看着账单涨起来

开一个临时目录，塞一个它必须自己找出来的 bug，然后跑。

```sh
go build -o agent ./stages/00-loop
mkdir -p sandbox && cd sandbox
# ... 往这里放一段坏掉的代码 ...
export AGENT_BASE_URL=... AGENT_API_KEY=... AGENT_MODEL=...
../agent
> 这个目录的代码里有个 bug。找出来、修掉、再验证一遍。
```

下面是一次真实运行的 token 账，六个回合（找 bug → 读文件 → 跑一遍 →
打补丁 → 再读 → 验证）：

| 回合 | 它干了什么 | prompt token |
|---:|---|---:|
| 1 | `ls -la` | 429 |
| 2 | `cat README.md && cat stats.py` | 613 |
| 3 | `python stats.py` → traceback | 737 |
| 4 | `sed -i ...` 打补丁 | 932 |
| 5 | `cat stats.py` | 1079 |
| 6 | `python stats.py` → 干净了 | 1192 |

把右边那列加起来：**计费 4982 个 token**，而这段对话最终只有
**1192 个 token**。做出来的东西值 1192，我们付了 4.2 倍。

这不是代码里的 bug，这就是"每回合重发整个历史"的字面含义，而且它是
平方级的：一个 40 回合的会话，最早那几个回合要付四十遍钱。任何一个
认真的 Agent 都得给出对策。我们的对策在**阶段 04**——同一个实验跑两遍，
一遍开缓存，一遍加 `--break-cache`，差多少就有数了。

这张表留着。后面整个仓库都拿它当基准线。

## 故意没做的那些

下面每一条都是阶段 01 的题目。别急着看补丁，先想办法把它们一个个踩出来
——踩坑的印象比补丁深得多。

| 缺什么 | 怎么把它踩出来 |
|---|---|
| 输出截断 | 让它 `find /`，或者读一个大文件，看上下文窗口被噪音填满。 |
| 命令超时 | 让它起一个开发服务器，然后 Agent 就永远挂在那儿了。 |
| 进程树清理 | 就算有超时，被杀掉的 shell 照样能留下一堆孤儿子进程。 |
| 权限闸 | 没有任何东西挡得住 `rm -rf`。所以才要你用临时目录。 |
| 流式输出 | 模型说话的整个过程，你只能盯着一个空终端。 |
| `finish_reason` | 我们只判断"有没有工具调用"。`length`（撞到 `max_tokens`）会被当成正常说完，一声不响。 |

`maxTurns` 这道保险丝是唯一提前进来的保命功能。少了它，一个卡在重试
循环里的模型能趁你读这个文件的工夫把你的 key 烧掉。

## 线上观察

真实 API 干过的事，`main.go` 里的类型不得不为它们让路：

- **带工具调用的那一回合，`content` 回来是 `null`**，不是 `""`。Go 的
  `json.Unmarshal` 碰到 null 什么也不做，所以一个普通 `string` 字段能扛
  过去——换一门对 null 更严格的语言，这里就炸了。
- **`tool_calls[].function.arguments` 是 JSON *字符串*，不是对象。**
  必须解析它，永远不要拿字符串去匹配。
- **会思考的模型还会多给一个 `reasoning_content`。** 这一阶段直接丢掉；
  阶段 02 会把它画出来，阶段 03 讲它怎么对应到 Anthropic 协议的
  `thinking` 块。

## 练习

1. **把 tool_call 的配对弄坏。** 故意少 append 一条 `role:"tool"` 消息，
   然后读 API 回的错误。这一下学到的协议知识比读文档多。
2. **把系统提示词删掉。** 看 Agent 怎么退化——它会开始让**你**去跑命令。
   所谓"Agent 效果"，大半就住在那个字符串里。
3. **把 `maxTokens` 改成 100。** 这时 `finish_reason` 会回 `length`，
   Agent 说到一半被截断，还一声不响。阶段 01 修的就是这个。
4. **换个模型指过去。** 任何 OpenAI 兼容的端点都行，本地 Ollama 也算。
   小模型会产出不合法的工具调用——那不是你的代码坏了，而且值得早点
   见一次。
